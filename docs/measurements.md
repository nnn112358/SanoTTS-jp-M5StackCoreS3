# 実機の数値

M5Stack CoreS3 / ESP-IDF v5.5.5 / -O2 / 240 MHz / PSRAM ON / 22.05 kHz 直接再生。
同じ文 `今日は良い天気ですね。`（53 ids / 106 frames / 27,136 sample / 音声 1.231 s）。
2026-09-02 実測。数値はシリアルログの `----- 結果 -----` ブロックから。

## 速度

| | W8A32 / PIE 無効 | **W8A8 + PIE（既定）** |
|---|---:|---:|
| `saan_stream_init` | 68.95 ms | **23.19 ms** |
| 初回 pull（受容野 38 フレームの warmup） | 2,546.98 ms | **766 ms** |
| 2 回目以降の pull（1 チャンク = 8 frames = 92.88 ms の音声） | 448.95 ms | **144 ms** |
| **定常 xRT**（pull 時間 ÷ チャンクの音声長） | 4.834 | **1.554** |
| ストリーミングでの途切れ | 10 / 14 チャンク | 10 / 14 チャンク |
| `-DSAAN_BUFFERED=1` の発話開始までの待ち | — | **2.68 s** |

- PIE で 3.1 倍速くなったが、**1.55× RT で実時間に届かない**。ストリーミングの途切れ回数は
  xRT が 1.0 を切るまで変わらない（途切れない条件はプリロール ≥ xRT × 音声長 / (1 + xRT) で、
  1.55 なら音声の 61% を先に貯める必要がある = ほぼ全部）
- 待ち時間 ≒ 音声長 × 1.55 + 初回 pull 0.77 s
- 残る 0.6% の depthwise はチャネル方向のギャザーで PIE に載らない（sanoTTS-jp M-58）
- 論文の 0.22× RT（英語 / ESP32-S3）とは 7 倍離れている。原因は未調査
  （候補: 重みが flash 上で D-cache 64 KB に載り切らない / iSTFT の float FFT /
  2 コア未使用 / M5 側のタスク切替）

## 正しさ

| | FNV-1a | \|max\| | Σx² |
|---|---|---:|---:|
| W8A32 / PIE 無効 | `0x78c209af06affc01` | 9529 | 74,155,592,149 |
| W8A8 + PIE | `0x04de91103a0e49f9` | 9744 | 74,374,063,946 |

- 出力 int16 列の FNV-1a と振幅統計。**両構成とも sanoTTS-jp の QEMU 記録（M-62）と
  27,136 sample すべて bit 一致**。移植の正しさは「音が鳴った」ではなくこれで確認している
- W8A32 と W8A8 で値が違うのは活性化を int8 に量子化するから（モデルは同じ blob）。
  W8A8 の品質差は SCOREQ で検出されない（sanoTTS-jp M-55）
- タッチ再生を含む連続 6 発話が同じ checksum = 発話ごとの統計リセット（`saan_pcm_reset`）が効いている
- 22.05 kHz 直接再生にしても checksum は変わらない（レートは M5 に渡した後の話）

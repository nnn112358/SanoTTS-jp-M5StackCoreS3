## 速度（旧コア、2026-09-02）

| | W8A32 / PIE 無効 | **W8A8 + PIE（既定）** |
|---|---:|---:|
| `saan_stream_init` | 68.95 ms | **23.19 ms** |
| 初回 pull（受容野 38 フレームの warmup） | 2,546.98 ms | **766 ms** |
| 2 回目以降の pull（1 チャンク = 8 frames = 92.88 ms の音声） | 448.95 ms | **144 ms** |
| **定常 xRT**（pull 時間 ÷ チャンクの音声長） | 4.834 | **1.554** |
| ストリーミングでの途切れ | 10 / 14 チャンク | 10 / 14 チャンク |
| `-DSAAN_BUFFERED=1` の発話開始までの待ち | — | **2.68 s** |

- PIE で 3.1 倍速くなったが、**1.55× RT で実時間に届かない**。ストリーミングの途切れ回数は
  xRT が 1.0 を切るまで変わらない（途切れない条件は先読み P ≥ T × (1 − 1/xRT) で、
  1.55 なら音声の 35.5%。⚠️ かつて 61% と書いたが誤り。docs/design-notes.md 参照）
- 待ち時間 ≒ 音声長 × 1.55 + 初回 pull 0.77 s
- 残る 0.6% の depthwise はチャネル方向のギャザーで PIE に載らない（sanoTTS-jp M-58）
- 論文の 0.22× RT（英語 / ESP32-S3）とは 7 倍離れている。原因は未調査
  （候補: 重みが flash 上で D-cache 64 KB に載り切らない / iSTFT の float FFT /
  2 コア未使用 / M5 側のタスク切替）

## 正しさ（旧コア、2026-09-02）

| | FNV-1a | \|max\| | Σx² |
|---|---|---:|---:|
| W8A32 / PIE 無効 | `0x78c209af06affc01` | 9529 | 74,155,592,149 |
| W8A8 + PIE | `0x04de91103a0e49f9` | 9744 | 74,374,063,946 |

- ⚠️ **2026-09-04 の同期後はこの値にならない**（上の節。新コアの期待値は `0xa69a7ebbb5ccb05f` / `0xe4b645c30835d42d`）
- 出力 int16 列の FNV-1a と振幅統計。**両構成とも sanoTTS-jp の QEMU 記録（M-62）と
  27,136 sample すべて bit 一致**。移植の正しさは「音が鳴った」ではなくこれで確認している
- W8A32 と W8A8 で値が違うのは活性化を int8 に量子化するから（モデルは同じ blob）。
  W8A8 の品質差は SCOREQ で検出されない（sanoTTS-jp M-55）
- タッチ再生を含む連続 6 発話が同じ checksum = 発話ごとの統計リセット（`saan_pcm_reset`）が効いている
- 22.05 kHz 直接再生にしても checksum は変わらない（レートは M5 に渡した後の話）

## 端末内漢字 G2P（2026-09-02、`logs/2026-09-02_kanji_test.log`）

`-DSAAN_KANJI=1`（既定）。辞書 `k1-dict-438750.bin` を `dict` パーティションから mmap。

| 項目 | 実測 |
|---|---:|
| 辞書 | 見出し語 355,768 / エントリ 438,750 / 接続行列 1377×1377、mmap 14,614,528 B |
| flash mmap の空き（PSRAM 8 MB 有効） | 22.7 MB（辞書の前）|
| 起動直後 / 辞書 mmap 後の内部 DRAM free | 90,939 B → 63,955 B |
| `今日は良い天気ですね。` | 形態素 7 → **53 ids / 27.5 ms** → checksum **`0x04de91103a0e49f9`**（かな中間表現からの合成と bit 同一） |
| `東京タワーの高さは333メートルです。` | 形態素 9 → 76 ids / 39.6 ms → 47,360 sample（2.15 s）、xRT 1.488、追い越し 0、発話開始まで 2,491 ms |
| イメージ / 静的 DIRAM | 1,383,872 B（factory 2 MB の 66%）/ 326,731 B（残り 15,029 B） |

- 漢字文から端末内で作った音素 ID 列が、ホストの OpenJTalk（フル辞書）で作ったかな中間表現からの列と
  **同じ checksum** になった = この文では枝刈り辞書でも読み・アクセントが一致している
- G2P は 1 文 30〜40 ms で、合成（数秒）に対して無視できる
- ⚠️ `CONFIG_SPI_FLASH_ROM_IMPL=y` だと辞書の mmap が `ESP_ERR_NO_MEM` で落ちる（ROM の旧実装に
  差し替わる）。`n` に戻した（IRAM 約 8 KB 増）
- ⚠️ 静的 DIRAM の残りが 15 KB と薄い。足りなくなったら `-DSAAN_CORE_IRAM=0`（+10 KB、xRT +2.4%）

- ひらがなだけの文でも辞書で形態素に切ってアクセントが付く（かな中間表現を手で書く必要が無い）
- 短い文ほど発話開始が早い（先読み量が音声長に比例するため）。挨拶 1 語で約 1.4 s
- xRT が文によって 1.25〜1.58 と揺れるのは、短い文では初回 pull の warmup の比率が変わるのと、
  チャンク数が少なく平均が粗いため
